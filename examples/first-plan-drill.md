# 第一次用 improve 演练 | First improve drill: audit, plan, execute, reconcile

在一个小仓库上把关键动作走一遍，先看硬规矩，再动手：

1. **装上**：在仓库根目录打开你的编程 agent，跑 `npx skills add shadcn/improve` 装好 skill。
2. **便宜档探底**：先跑 `/improve quick`，只看热点和头部发现，确认产出的发现表带 `文件:行号` 证据、影响、工作量和置信度。质量不行就停在这里，别往下花钱。
3. **挑一条写计划**：从发现表里挑一条小的（比如一条 S 级工作量的），回它编号让它写计划；计划应落进 `plans/` 并带索引。逐项检查：路径与现状代码摘录是否齐、每步结尾是否有验证命令与预期输出、范围外清单与 STOP 条件是否写死、计划头有没有盖写它时的 git commit。
4. **复核计划**：跑 `/improve review-plan <那份计划>`，看它能不能挑出计划自己的毛病——这一步是把计划交给弱模型之前的最后一道人工加机器检查。
5. **隔离执行**：跑 `/improve execute <计划编号>`，看它是否在隔离 worktree 里派便宜模型执行、复核时是否逐条重跑完成标准。注意：合并永远由你定，它给的结论只有通过、打回（最多两轮）、卡住三种。
6. **收尾对账**：过几天再跑 `/improve reconcile`，看它如何核对已落地的计划、解开卡住的、退役过时的——计划不是发完就算完，这一圈闭环走通，才算把这套分工真正用起来。
